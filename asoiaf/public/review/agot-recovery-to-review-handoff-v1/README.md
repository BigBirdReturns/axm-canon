# AGOT physical recovery to review handoff v1

This repository surface carries the exact Windows-first physical recovery and private-locator handoff that follows the forty-five AGOT opening-gate review intakes. The reconstructed ZIP is an operating package, not a source object, review transaction, canon transaction, or private-estate admission.

The exact package is `asoiaf-agot-recovery-to-review-handoff-v1.zip`, 107,565 bytes at SHA-256 `dd70c8c9d5de23db7014d8e4d89b73a52d24ecedc8986c4e42812e7820a390d9`. It expands to forty-five files. Git stores nineteen ordered RFC 4648 base64 chunks totaling 143,420 characters at SHA-256 `ed5b5c481488c0e68887702bb6c0c36ac775677887638cde51e39b979d2af819`. The first fifteen chunks contain 9,000 characters each. The final 8,420-character segment is represented by four ordered 2,105-character files. `CARRIER.json` fixes every path, character count, digest, Git blob identity, concatenation order, decoded byte count, and decoded ZIP digest.

The first merged carrier tree did not match that metadata. It omitted three declared paths and retained five divergent or truncated chunk objects, so the reachable tree could not reconstruct the admitted ZIP. `REPAIR.json` preserves the exact defect and correction. The repair changes carrier layout only. The concatenated base64 identity and decoded ZIP identity remain unchanged.

The package scans fixed and removable Windows drives for four exact objects: the holder-controlled AGOT EPUB, the six-edition source vault, the compiled private-estate v1 archive, and the qualified private SQLite corpus. It hashes only plausible candidates and records clear paths in a local-only receipt. It does not copy, move, rename, delete, extract, mount, upload, download, or display source content.

When the exact private SQLite corpus is recovered, the handoff re-verifies its byte count and SHA-256 and invokes the qualified locator operator with fixed arguments. A successful run resolves forty-five atomic candidates to thirty-one metadata-only paragraph envelopes. It does not return paragraph prose or execute a decision. When only the exact EPUB, source vault, or private-estate archive is recovered, the package returns `EXACT_SOURCE_RECOVERED_CORPUS_RESTORE_REQUIRED` and refuses extraction or rebuilding. When no exact object is found, it retains `HOLD_PHYSICAL_RECOVERY`.

The next bounded surface is the [`../agot-local-human-review-workstation-v1/`](../agot-local-human-review-workstation-v1/README.md) loopback workstation. It can be used only after the exact qualified SQLite corpus is recovered. It displays one paragraph at a time to a named reviewer and saves text-free, unexecuted review intakes.

The binary ZIP path is intentionally absent from Git. Carrier reconstruction proves package identity only. It does not materialize any private source, authorize archive extraction, satisfy human review, promote canon, or mutate the graph. The current standing remains `HOLD_PHYSICAL_LOCAL_RECOVERY_REQUIRED` with zero review transactions, zero automatic canon promotions, and zero graph mutations.

The upstream transaction intake is recorded at [`../agot-opening-gate-review-intake-v1/`](../agot-opening-gate-review-intake-v1/README.md), and the connected-venue search receipt is recorded at [`../agot-source-recovery-sweep-v1/`](../agot-source-recovery-sweep-v1/README.md). The control question is whether an exact local object can be recovered and verified without allowing a filename, near-sized file, historical path, checksum receipt, carrier reconstruction, or successful workflow to impersonate the required private bytes or a completed human review.
